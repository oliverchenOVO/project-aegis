# Counterfactual replay — Milestone G

A verified timeline owns parsed copies of the scenario and record, cold checks the complete parent, then restores the nearest complete checkpoint. A fork stops before commands at its exact tick. Commands before that tick are retained; the caller supplies the complete ordered future command plan, allowing removal, replacement and addition. The strict command schema rejects arbitrary world edits. An exact pre-command fork checkpoint is inserted between periodic boundaries.

Each branch records branchId, parentReplayId, parentHash (the parent's final canonical world hash), forkTick, baseHash, simulationVersion and scenarioVersion. Identity also commits to the alternative command plan and requested horizon. Commands beyond early completion remain explicitly unapplied. Nested forks refer to the saved parent's branch ID. Branch saves contain their own snapshots, commands and events and reopen through the normal independently verified save loader.

Session forks preserve the original simulation, save and replay. Comparisons derive counted deaths, critical cases, incidents, hospital overload hospital-seconds, grid outage seconds, communication node outage service-seconds, response times and received command acknowledgement delays from actual simulations. Response means the first actual arrival at each incident; EMS response has its own numerator/count. Zero response observations are displayed with count zero and must not be interpreted as instant response. Unit utilization is an estimate from authoritative unit observation intervals, not from received positions. Different completion durations are reported separately. Zero metric deltas are retained.

Population origin IDs match changed death outcomes across independently generated patient splits. References identify real events in each timeline; an empty alternative death list means there was no corresponding death, not an invented event. Parent/hash mismatches fail rather than generating an explanation.

## Reproducible demonstration and failed probe

Run `pnpm exec tsx benchmarks/counterfactual.ts 3`. At second 30, the original sends all six ambulances to INC-1. The alternative retains AMB-05/06 and dispatches them at second 350 to the received, EMS-compatible incident at N23. The script verifies repeat forks, cold replay, save/reopen and parent immutability before accepting the demonstration. No outcome is hardcoded; the showcase gate requires a real reduction in deaths for its named seed.

The initial flood scenario 1.2.0 probe produced a zero death delta, recorded in `qa/counterfactual-initial-zero-delta.json`. Inspection confirmed four critical patients were collected but both ambulances became stranded at N22 as water overtopped the 1.5 m hospital corridor. Scenario 1.3.0 raises those two configured access edges to 2.5 m for every seed. This is an explicit scenario balance change, with no seed-dependent rescue rule or altered patient outcome logic. The named seed then produced original 901 deaths, alternative 897, and four actual recoveries. Both hospital overload durations remained zero. Final multi-seed evidence is in `qa/counterfactual-showcase.json`; figures there take precedence over this first probe.

## Validation and failure handling

Nine branch tests cover three seeds, fork boundaries 0/299/300/301/600, same-command exact equivalence, immutable caller inputs, invalid plans/world edits, cold replay, checkpoint continuation, save/reopen, nested lineage, systemic earthquake/flood and Session isolation. Invalid lineage/base hashes and commands after completion fail explicitly. The full 88-test suite passed in 100.18 seconds; after adding explicit alternativeCommands lineage metadata, the nine affected tests passed again in 14.84 seconds. Typecheck, lint and production build passed. The complete three-seed demonstration was rerun with this metadata: death deltas were -4/-4/-3, with zero replay/save/determinism/parent-mutation failures. Original run times were 8.06/11.69/8.55 seconds for 2400 ticks; branch simulation times were 3.82/3.83/3.95 seconds. These are local probes, not the final 200-seed or Windows release gates.

The initial Session byte-equality assertion found ZIP wall-clock timestamps, although canonical worlds were identical. Format-2 archives now use a fixed DOS epoch metadata timestamp, making identical validated saves byte-reproducible. No clock enters authoritative simulation state; the frozen legacy format-1 implementation remains untouched.
