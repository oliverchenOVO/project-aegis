# Routed communication and source capabilities

Systemic earthquake 2.2.0 and urban flood 1.2.0 explicitly enable a communication topology. Earthquake v1 and the frozen v0.1 compatibility engine keep their released transport behavior; the legacy factory rejects new features. This is a deterministic packet macro model, not radio propagation or an external network service.

The scenario supplies 13 nodes and 22 bidirectional links: dispatch, repeater, cell tower, four agencies, two hospitals and four district/flood-zone gateways. Nodes depend on independent power, grid power with counted backup fuel, or a real hospital's power/generator. A configured tower flood threshold and active repeater damage also affect node availability. Grid backup draws one unit per simulation second and recharges when the grid is restored. NORMAL/DEGRADED/DOWN transitions cite their actual flood, incident, power or prior backup transition causes.

Each link defines integer latency, reliability and packets-per-tick capacity shared by both directions. A degraded endpoint doubles latency, reduces reliability and halves bandwidth (minimum one packet/tick). Stable shortest paths avoid down nodes and already visited nodes. Queue processing is FIFO by deterministic insertion order; full link bandwidth leaves the packet queued and increments its actual queue delay. Independent narrower agency circuits provide slower routes after shared infrastructure fails. A backup hop directly references the failed/degraded nodes on its nominal route; causal links do not infer failures from nearby timestamps.

Reports, player commands and return acknowledgements all travel as packets. Every queue, hop departure/arrival, terminal loss and delivery is in the event ledger. Link loss uses persisted seeded message streams. Unreachable packets wait for possible recovery and expire after 450 seconds with an explicit reason/cause. Source transmission, destination receipt and return acknowledgement are distinct times. Receipt cannot precede transmission; acknowledgement cannot precede command delivery.

Only active packets stay in authoritative network queues after a tick; terminal packets remain fully represented by immutable events and their report/command results. This avoids duplicating completed transport history in checkpoints. Snapshots include active hop endpoints/deadlines, visited nodes, queue delay, message sequence, peak pending count, node backup/status causes and RNG streams. Queue plus scheduled-event limits fail explicitly at 20,000; player/report submissions check capacity before adding records. Invalid initial endpoint references fail before the scenario starts.

Sources declare endpoint, location, supported subject kinds, optional incident types, reliability and confidence range. Sensors observe their own flood zone; hospital reporters observe their own hospital; unit self reports observe that unit, and incident reports require its actual operating assignment. Local civilian reports are noisy; fire observation posts cannot report mass-casualty cases or unrelated locations. Utility, radio and traffic controls have distinct telemetry capabilities. Unsupported observations do not create reports. Civilian population estimates use a separate `POP-<zone>` subject so they cannot overwrite a water-level belief.

Hospital observations now include the observed census, queue, ICU occupancy, vehicle handover count, status and powered state. Civilian observations include noisy local population, injury and critical counts. They pass through the same physical transport and knowledge boundary as other claims. Current authoritative hospital/cohort/network values never replace received claims.

The live command DTO shows SENT/PENDING until an acknowledgement actually returns, then its last reported execution outcome. Completion and receiver refusal also return through the network. Later unreceived world changes cannot alter the player's known result. Missing confirmation eventually produces an explicit timeout from elapsed time; packet loss alone is not disclosed as immediate omniscience. AAR may inspect the complete historical ledger.

Path caches contain derived computation only, keyed by topology status/geometry/latency plus source/destination/visited nodes. They are excluded from hashes and discarded on topology changes or restored world identity. The first uncached flood probe measured 123.35 ticks/sec, below the release floor. The same-seed cached probe measured 559.08 ticks/sec with zero invariant/replay/save failures (`qa/comms-probe*.json`). These are development probes, not release results. The final milestone three-seed measurement is `qa/communication-performance.json`.

Nine communication tests cover source/locality restrictions, bandwidth/congestion, return ACK knowledge, backup exhaustion and outage causal references, isolation expiry, fog boundaries, pending checkpoint continuation, malformed topology and guards. Earlier complete isolated 66- and 67-test runs passed. A concurrent benchmark/full-test run exceeded the unchanged 30-second limit for one flood test; a later two-worker run exceeded it for all three combined flood cases. Each combined case performed four independent full validations in one test. They are now separate hazard, cold replay/AAR, verified seek, encoding and reopening checks, sharing an immutable completed fixture that is released after its suite. No assertion was removed; every stage and fixture generation retains a 30-second bound. The focused three-seed flood suite passed all 18 checks in 112.68 seconds total. Full-timeline tests use at most two Vitest workers to bound duplicated checkpoint memory. The final complete 79-test suite passed in 148.90 seconds; lint, typecheck and production build also passed. Latest three-seed throughput is 356.60 ticks/sec, above the 200 release floor but below the 500 target; no final release claim is made from these three seeds. Final 200-seed release verification is still pending.
