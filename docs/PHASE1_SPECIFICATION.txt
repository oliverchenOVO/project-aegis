可以。這個專案值得把底層一次設計對，因為它的亮點不是「地圖上很多救護車在跑」，而是 **玩家永遠看不到完整世界，只能透過延遲、錯誤、互相矛盾的情報做決策，而世界會按照真正狀態繼續演化**。

我先替它定一個工作代號：

# Project AEGIS
**AI Disaster Command Center / AI 災難指揮中心**

---

# 0. 產品定位

它不應該被做成：

> 災害版 RTS + 幾個 AI 對話框

而應該是：

> **Deterministic Emergency Management Simulation × Information Fog × Incident Command System × Counterfactual Replay**

最終玩家看到的是一套像真的「緊急應變中心」的軟體：

```text
┌─────────────────────────────────────────────────────────────────┐
│  PROJECT AEGIS     INCIDENT #TW-042       14:37:22   SIM ×4   │
├──────────────────────────────┬──────────────────────────────────┤
│                              │ INCIDENT FEED                    │
│           CITY MAP           │                                  │
│                              │ 14:36 Fire Dept: Building fire   │
│   🔥         🚑               │ 14:35 Hospital: Generator issue │
│          ⚡                  │ 14:33 Police: Bridge blocked    │
│      🏥                      │                                  │
│                              ├──────────────────────────────────┤
│                              │ COMMAND QUEUE                    │
│                              │                                  │
│                              │ > Dispatch ENG-04 to Sector C    │
├──────────────────────────────┴──────────────────────────────────┤
│ UNITS  42/57  │ CASUALTIES ? │ POWER 71% │ COMMS DEGRADED     │
└─────────────────────────────────────────────────────────────────┘
```

但這張畫面顯示的 **不是 GameState**。

它是：

```text
ObservedState ≠ WorldState
```

這一點必須從架構第一天就成立。

# 1. 核心玩法與差異化

## 核心 Loop

每一局基本循環：

```text
災害發生
    ↓
世界真實狀態演化
    ↓
單位 / 感測器 / 平民觀察事件
    ↓
情報產生
    ↓
延遲 / 遺失 / 誤判 / 矛盾 / 通訊中斷
    ↓
指揮中心收到部分情報
    ↓
玩家形成判斷
    ↓
發布命令
    ↓
單位接收 / 延遲 / 無法執行 / 修改執行
    ↓
影響真實世界
    ↓
產生新情報
```

玩家管理的其實有四種東西：

| 資源 | 說明 |
|---|---|
| Physical Resources | 消防車、警力、救護車、醫院床位、發電能力 |
| Time | 越晚處理，事件可能進入不可逆狀態 |
| Information | 情報可能不完整、過時甚至錯誤 |
| Attention | 玩家不可能同時處理所有事件 |

---

## 第一個核心差異化：Information Fog

傳統模擬：

```text
Fire = severity 83
Hospital = power 12%
Casualties = 37
```

玩家直接看到。

AEGIS 必須變成：

### World Truth

```text
Sector B Hospital
power = 3%
generatorFuel = 11 minutes
icuPatients = 38
generatorFailureRisk = 0.72
```

### Command Center Belief

```text
Hospital B
powerStatus = UNKNOWN
lastReport = 14 minutes ago
reportedGenerator = "operational"
confidence = 0.61
```

玩家甚至可能收到：

```text
14:13 Hospital B:
"Backup generator stable."
```

但現在已經是：

```text
14:27
```

而 14:19 發生燃料管線破裂。

所以情報不是 boolean：

```ts
known / unknown
```

而是：

```ts
{
  claim,
  source,
  observedAt,
  reportedAt,
  receivedAt,
  confidence,
  reliability,
  expiry,
  corroboration
}
```

---

# 2. 第二個核心差異化：因果系統

AAR 不能只是：

> 你死了 43 人，評分 B。

每個重大結果都應該可追溯。

例如：

```text
Hospital B evacuation failed
       │
       ├── ambulance shortage
       │       └── 8 ambulances dispatched to Sector A
       │
       ├── power failure
       │       └── generator fuel exhausted
       │
       └── evacuation order arrived 11 min late
               └── radio repeater offline
```

甚至往玩家命令追：

```text
14:07
PLAYER
"Send all available ambulances to Sector A"

↓

Sector B retained only 2 ambulances

↓

14:21
Hospital B evacuation requested

↓

insufficient transport capacity

↓

+12 critical casualties
```

這就是整個產品最重要的資料：

# Causal Graph

而不是事後讓 LLM 猜「可能是因為……」。

---

# 3. 第三個核心差異化：Counterfactual Replay

AAR 裡可以選：

> 如果我 14:07 沒有派出所有救護車呢？

Simulation 從指定 tick fork：

```text
Original timeline
───────────────●──────────────────────>
               14:07

Alternative
               └──────────────────────>
                 Keep 4 ambulances
```

接著 deterministic simulation 重新跑。

例如：

```text
ORIGINAL
Fatalities: 41

COUNTERFACTUAL
Fatalities: 29

Difference:
-12 fatalities

Primary causal difference:
Hospital B evacuation completed 8m 41s earlier.
```

這會是非常強的展示功能。

# 4. 世界架構

我建議採：

# Fixed-step deterministic discrete simulation

不要讓模擬世界直接依靠：

```ts

Date.now()
Math.random()
```

而是：

```text
Tick 000001
Tick 000002
Tick 000003
...
```

例如：

```text

```

UI：

```text
Paused
×1
×2
×4
×8
```

只是控制一秒執行多少 simulation ticks。

不是改變 simulation 規則。

# 6. Simulation architecture

建議不要一開始上完整 ECS framework。

這個遊戲主要是：

- 事件
- 資源
- 狀態
- 時間
- 網路
- 因果

所以採：

# Entity + Component-like state + Systems + Event Queue

例如：

```ts
interface WorldState {
  tick: number;
  entities: EntityStore;
  incidents: IncidentStore;
  infrastructure: InfrastructureState;
  communications: CommunicationState;
  intel: IntelState;
  causalGraph: CausalGraph;
}
```

每 tick：

```text
advanceSimulation()

1. resolve scheduled events
2. update disasters
3. update infrastructure
4. update population
5. update medical system
6. update responder units
7. update communications
8. generate observations
9. transmit intelligence
10. resolve commands
11. emit domain events
12. update causal graph
```

順序必須固定。

不能某一次：

```text
fire → ambulance
```

另一次：

```text
ambulance → fire
```

否則 Replay 會飄掉。

---

# 7. RNG 系統

只能存在一個 deterministic random abstraction：

```ts
interface RandomSource {
  next(): number;
  integer(min: number, max: number): number;
  chance(probability: number): boolean;
}
```

禁止 simulation code 使用：

```ts
Math.random()
```

建議：

```text
seed
↓
scenario RNG
↓
named streams
```

例如：

```text
seed: AEGIS-2026-001

fireSpread
population
communications
medical
unitDecisions
```

進一步可以：

```ts
rng.stream("fire:incident-17")
```

這樣新增 UI 或非關聯事件，不容易造成整個 RNG sequence 改變。

# 12. Infrastructure graph

道路、醫院、電網、通訊最好不是獨立假的數值。

使用 Graph：

```text
Power Plant
 │
 ├─ Substation A
 │   ├─ Hospital
 │   └─ Radio Tower
 │
 └─ Substation B
```

道路：

```text
Node
↓
Edge
↓
Node
```

所以：

```text
bridge collapse
```

真的會造成：

```text
route unavailable
↓
ambulance reroute
↓
+5 min arrival
↓
patient deteriorates
```

這才能產生 emergent gameplay。

# 13. Disaster System

不要寫一個：

```ts
class EarthquakeGame
```

而應該：

```text
Hazard
↓
Effects
↓
World Systems
```

例如 earthquake：

```text
Ground shaking
├── structural damage
├── road damage
├── power damage
├── communications damage
└── injuries
```

Fire：

```text
Fire
├── intensity
├── fuel
├── spread probability
├── suppression
└── structural damage
```

Flood：

```text
FloodZone
├── depth
├── flow
├── road passability
├── building damage
└── electrical risk
```

這樣未來可以同時：

```text
Earthquake
↓
Power failure
↓
Hospital generator
↓
Fire
↓
Communications overload
```

而不是獨立 minigame。

# 15. 哪些可以使用 LLM

LLM 是 enhancement。

不是 simulation authority。

### 適合 LLM

```text
消防隊無線電自然語言
醫院求援文字
市政府 briefing
平民 911 報案
新聞報導
角色 personality
AAR 自然語言摘要
高階 AI advisor
NPC 對玩家命令的自然語言回覆
```

例如 simulation 決定：

```json
{
  "type": "REQUEST_ASSISTANCE",
  "incident": "INC-4",
  "severity": "critical",
  "requestedResources": {
    "ambulance": 4
  }
}
```

LLM 可以轉成：

> 指揮中心，這裡是第三消防分隊。現場傷患數持續增加，我們至少還需要四輛救護車，情況非常緊急。

但 LLM **不可以決定**：

> 現在需要 4 台救護車。

4 是 simulation 算的。

正式儲存檔例如：

```text
AEGIS_SAVE_20261003_1421.aegis
```

內部 zip container。

之後如果典藏幾百局需要搜尋，再建立：

```text

```

但是 replay source of truth 仍然是 portable package。

# 26. Replay

Replay 格式：

```ts
interface ReplayManifest {
  formatVersion: number;

  simulationVersion: string;

  scenarioId: string;

  scenarioVersion: string;

  seed: string;

  commands: PlayerCommand[];

  checkpoints: CheckpointIndex[];
}
```

完整 Replay：

```text
load scenario
↓
set seed
↓
run ticks
↓
at tick 311 apply player command
↓
continue
```

每：

```text
300 ticks
```

可以建立 snapshot。

因此 seek：

```text
00:00 → 02:41
```

不用從 tick 0 重跑。

---

# 27. Replay integrity

每 N ticks 計算：

```text
stateHash
```

例如：

```text
tick 0
hash F911...

tick 600
hash A928...

tick 1200
hash C211...
```

Replay 再跑時：

```text
expected == actual
```

不同直接報：

```text
DETERMINISM REGRESSION
```

這會極大提升長期維護品質。

# 2. Non-Negotiable Architecture Rules

以下為硬性要求。

## Rule A — Deterministic Simulation

Simulation core 不得依賴：

- Math.random()
- Date.now()
- performance.now()
- browser timers
- network calls
- LLM

所有 simulation randomness 必須經由 seeded deterministic RNG abstraction。

同一：

- simulation version
- scenario version
- seed
- player command stream

必須產生相同：

- authoritative world state
- event sequence
- final result
- deterministic state hashes

---

## Rule B — UI Cannot Access World Truth

Normal gameplay UI 不得直接讀取 authoritative WorldState。

UI 只能讀：

CommandCenterView / KnowledgeState / ReadModel

World Truth 僅允許：

- simulation internals
- automated tests
- explicit developer/debug truth mode

使用。

請以 module boundaries 和 tests 防止意外破壞這項規則。

---

## Rule C — LLM Cannot Control Truth

Phase 1 不需要 LLM 才能完整遊玩。

Simulation 不可依賴 LLM。

未來 LLM 可負責：

- radio dialogue
- natural-language briefings
- narrative
- advisor responses
- AAR prose

但 LLM output 永遠不得直接 mutate authoritative simulation state。

請預留乾淨 interface，但 Phase 1 不需整合商業 API。

---

## Rule D — Headless Simulation

simulation package 必須能在完全沒有：

- Electron
- React
- DOM

的環境下執行。

應可從 Node CLI / tests 執行 scenario。

# 5. Simulation Clock

- ×2
- ×4
- ×8

# 6. Seeded RNG

至少：

- next()
- integer()
- chance()
- choose()

→ disaster stream
→ medical stream
→ communication stream
→ unit stream

# 30. Replay

Replay 的 authoritative inputs：

- simulation version
- scenario id/version
- seed
- player command stream

不要以 UI snapshots 取代 deterministic replay。

Replay 必須：

- 從 tick 0 完整重新模擬
- 套用相同 commands
- 產生相同 state hashes

支援：

- play
- pause
- ×1
- ×2
- ×4
- ×8
- timeline seek

為了 seek performance，可每固定 interval 儲存 deterministic checkpoint。

---

# 31. Replay Integrity

至少每 300 ticks 建立 canonical state hash。

Canonical serialization 必須避免不穩定 property ordering。

Test：

original run hashes
==
replay run hashes

任何 mismatch：

測試必須 fail。
